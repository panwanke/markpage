# 墨页 MarkPage

> [English](README.md) | 简体中文

本地优先的 Markdown 排版阅读与批注应用。Markdown 源文件是唯一的真相源：排版、标注、页面设置与评论全部随 `.md` 一起导出。

**在线使用**：[panwanke.github.io/markpage](https://panwanke.github.io/markpage/) · [markpage-dl2.pages.dev](https://markpage-dl2.pages.dev/)（镜像）—— 无需安装，打开即用。文档只存在浏览器本地，不上传任何服务器。

## 快速开始

```bash
npm install
npm run dev      # 开发预览 http://127.0.0.1:5173
npm run build    # 类型检查 + 生产构建
npm test         # 核心链路单元测试
npm run lint     # 静态检查
```

需要 Node.js 20.19+ 或 22.12+（Vite 8 的要求）；只有「本地文件夹」（File System Access API）要求 Chromium 内核浏览器，其余功能在 Firefox / Safari 下同样可用。

## 核心能力

| 能力 | 实现方式 |
| :--- | :--- |
| Markdown 排版 | unified / remark + rehype 管线，支持 GFM、脚注、表格、任务列表 |
| 公式与代码 | KaTeX 渲染行内与块级公式；highlight.js 只加载常用语言 |
| 双栏视图 | 左排版右源码并排：改源码左栏立刻重排，改排版（标注）右栏立刻更新；中间分隔条可拖动，双击复位，宽度随偏好保存 |
| 修订模式 | 新增写 `<ins>`、删除写 `~…~`，正文按 Word 习惯显示（绿色下划线 / 红色删除线）；源码编辑器里打字、退格、粘贴自动记修订；单条与整篇都能接受 / 拒绝；公式与代码块不参与修订 |
| 选区标注 | 在渲染正文上选字，加粗 / 删除线 / 高亮 / 行内代码 / 文字颜色 / 清除格式，直接写回源码 |
| 右键改色 | 正文上右键：高亮底色与文字颜色色板、当前颜色打勾、取消高亮 / 默认色、加粗、删除线、行内代码、清除格式、加评论、复制；右键落在高亮上时自动命中整段，不必先拖选 |
| 多轮评论 | `<comment id="…">` 锚点 + `> [!comment …]` callout，支持回复、解决、删除 |
| 页面系统 | A4 / Letter 实际测量分页，页眉页脚、页码、字号行距 |
| 工作区 | 多标签、本地自动保存、导入 `.md`、拖拽打开、源码模式、大纲、专注模式、打印 / PDF |
| 文件夹工作空间 | 可打开多个本地文件夹作为工作空间来回切换，带最近工作空间与最近文件（最多 20 条，按工作空间去重）；文件绑定 `workspaceId + path`，两个根下的同一路径不会串写 |
| 标签排序 | 拖动标签即可调整打开文档的顺序（`Alt` + `←` / `→` 也能移动），关闭着的文档留在原位不动 |
| 菜单栏与快捷键 | 顶部菜单栏把每条命令和它**当前生效**的键位一起列出来；键位可在 设置 → 快捷键 里逐条录制，冲突当场报出，不会悄悄覆盖 |
| 撤销 / 重做 | 每篇文档各持一份撤销栈，600ms 内的连续输入合并成一步；撤销的是全文快照，修订标记也一起回退 |
| 文档右键菜单 | 工作区列表项与标签栏共用同一份菜单：打开 / 重命名 / 复制一份 / 导出 .md / 保存到磁盘 / 从磁盘重新载入 / 复制路径 / 解除绑定 / 关闭 / 删除；键盘用 `Shift+F10` 或 Menu 键也能唤出，关闭后焦点回到触发处 |
| 磁盘绑定 | 直接连上磁盘目录（File System Access API），列出其中的 `.md`，点击即读、改完写回原文件；按文档防抖串行写盘、磁盘基准哈希检测冲突、只读与错误状态和浏览器缓存状态分开显示；普通文件夹一次最多收 2000 个文件（识别为 Obsidian 库的文件夹改走库扫描：8 层、5000 个文件），触顶会提示列表被截断 |
| 停靠侧边栏 | 示例库 / 工作区 / 大纲是可拖动的面板：拖到一起合并成标签页，拖到底部拆成新组，可关闭、可调宽度、可整栏隐藏；布局随偏好持久化 |
| 多语言 | 中 / 英双语，界面语言即时切换；词表按语言分文件，新增语言只需补一份并注册，类型检查保证不漏键 |
| 外观 | 界面字体与字号缩放（默认 115%，侧栏、状态栏与评论面板一并放大）、正文字体族；随偏好本地保存 |
| 三档导出 | **直接导出**原样带走；**纯净导出**剥掉 comment 锚点、评论块与高亮颜色；**自定义导出**按颜色把标签映射成自己的 class / 行内样式，带实时预览 |
| 插件接口 | 命令、渲染器、编辑模式、文档访问与生命周期 API（API 1.2）；内置插件可在「设置 → 插件」里启停，停用会一并摘掉它的命令、渲染器和编辑模式。插件命令单独收进**插件**菜单（与核心命令共享快捷键设置与冲突检测），渲染器跑在解析树的副本上——插件既弄不脏渲染缓存，抛错也带不垮整篇正文 |
| 实时编辑 | 可选内置插件：单条连续 CodeMirror 6 视图，非活动行隐藏 Markdown 标记、光标行显示标记；Markdown 仍是唯一真相，对中文输入法安全，默认关闭 |

页面设置写入 YAML Frontmatter；用户名、视图开关、语言、侧边栏布局与外观（字体 / 字号缩放）等偏好保存在浏览器本地。界面字号通过 CSS 变量 `--ui-scale` 统一缩放，侧栏与评论面板的宽度跟着 `--ui-width`（以默认 115% 为基准）一起放大，正文字体走 `--doc-font`，与文档自身的字号行距互不干扰。

## 双栏视图

工具栏的 `排版 / 双栏 / 源码` 三档切换。双栏 = 左边排版、右边源码，两边共用一个 `markdown` 状态：

- 在右栏改源码，左栏立刻重排；在左栏选字加标注，右栏立刻出现对应的 `**`、`<mark>` 等标记。
- 中间的分隔条可以拖动（源码栏占 22%–75%），双击复位到 42%，比例存在偏好里。
- 左栏在双栏下固定为连续视图 —— 纸张是 794px 宽，塞进半屏只会横向滚动；分页视图仍只在单栏排版模式生效。

## 菜单栏与快捷键

顶栏左侧是菜单栏：**文件 / 编辑 / 格式 / 修订 / 视图 / 库 / 标签页 / 帮助**。每一项右侧显示的键位都从当前键位表现算，改过快捷键后菜单立刻跟着变——菜单本身就是这份快捷键的说明书。

只要有启用的插件注册了命令，标签页与帮助之间就会多出一个**插件**菜单。插件命令不带键位、也不进 `COMMANDS`，因此既不会和核心快捷键撞车，也不能在「设置 → 快捷键」里改绑；菜单项就是它唯一的触发入口，停用插件后命令与菜单一起消失。

命令定义集中在 `src/lib/shortcuts.ts` 的 `COMMANDS` 里：一条命令 = id + 分组 + 文案键 + 默认键位。菜单栏、全局监听、设置面板都从这张表派生，新增命令只加一行，界面自动出现。

| 分组 | 默认键位 |
| :--- | :--- |
| 文件 | 新建 `Ctrl/⌘+Alt+N` · 导入 `+Alt+O` · 保存当前文件 `+S` · 直接导出在文件菜单 · 纯净导出 `+Shift+S` · 自定义导出 `+Alt+S` · 打印 `+P` · 设置 `+,` |
| 编辑 | 撤销 `+Z` · 重做 `+Shift+Z`（`+Y` 同样可用） · 删除选区 `Delete` |
| 格式 | 加粗 `+B` · 删除线 `+Shift+X` · 高亮 `+Shift+H` · 行内代码 `+Shift+C` · 清除格式 `+\` · 评论 `+Alt+M` |
| 修订 | 切换修订 `+Shift+R` · 标记删除 `+Alt+D` · 插入 / 替换 `+Alt+I` · 接受全部 `+Alt+Enter` · 拒绝全部 `+Alt+Backspace` |
| 视图 | 排版 / 双栏 / 源码 `+Alt+1/2/3` · 分页 / 连续 `+Alt+P` `+Alt+C` · 侧边栏 `+Shift+B` · 评论 `+Shift+M` · 专注 `+Shift+F` |
| 库 | 快速切换 `+O` · 跟随光标处的双链 `+Enter` · 在库里新建笔记 `+Shift+N` · 链接面板 `+Shift+L` |
| 标签页 | 上一个 / 下一个 `+Alt+←` `+Alt+→` · 关闭当前 `+Alt+W` |

上表里前缀相同的一律省略了 `Ctrl/⌘`。默认键位刻意绕开了浏览器的保留键（`Ctrl+N` `Ctrl+T` `Ctrl+W` `Ctrl+1..9`）：那些键在页面里 `preventDefault()` 也拦不住，写上去只会看起来「没生效」。

**改键**：设置 → 快捷键，点任意一行的键位就进入录制，按下组合即生效。三条规则：

- 必须带 `Ctrl/⌘` 或 `Alt`，或者本身就是 `Delete`、`F1–F12` 这类不会打断输入的键；`Esc` 取消、`退格` 清空（清空后这一项不占任何键）。
- 与别的命令撞车时**不覆盖**，直接报出占用它的那条命令名，让用户决定改哪一个。
- 录制期间全局监听临时停摆，否则录 `Ctrl+B` 会顺手把加粗真的执行一次。

**编辑快捷键**同时支持排版选区和源码编辑器（含双栏右侧）。加粗、修订等命令使用当前源码选区；撤销/重做在两种视图中共用文档历史。插入/替换也支持光标位置的纯插入。标题、对话框等普通输入框保留原生编辑按键；输入法组字和快捷键录制期间不触发正文命令。

重做保持默认键位时兼容 `Ctrl+Y`；清空或改绑重做会同时停用这个别名。单项恢复默认也会检查键位冲突。

键位表存在 `markpage.settings.v1` 的 `keymap` 字段里，只存与默认值的差异项也算完整表——读取时缺项落回默认、写坏的键位丢掉、空串（用户主动清空）保留。

## 标签页排序

标签栏用原生 HTML5 拖放：拖到目标标签的左半边插到它前面，右半边插到后面，拖动时源标签半透明、目标侧出现一条紫色指示线。窗口级的「拖入 .md 打开」只认 `Files` 类型，两套拖放不会互相抢事件。

重排只改**已打开**文档彼此的次序——文档数组里还躺着关闭着的文档，它们的槽位不动，所以左侧工作区列表的顺序不会被拖标签的动作打乱（`src/lib/tabs.ts` 的 `reorderOpenDocuments`）。键盘可达：标签聚焦后 `Alt` + `←` / `→` 左右挪一位。

## 打开文件

三种入口，落到同一个文档模型上，区别只在「内容住在哪」：

| 入口 | 内容来源 | 改动去向 |
| :--- | :--- | :--- |
| 导入 / 拖拽 | 文件内容拷进浏览器 | 只在浏览器里；要落到磁盘得再导出 |
| 本地文件夹 | 磁盘上的原文件 | 写回原文件（600ms 防抖，连续输入只落一次盘） |

**拖拽**：把 `.md` / `.markdown` / `.mdown` / `.mkd` / `.txt` 从资源管理器拖到窗口任意位置，出现虚线投放框后松手即可，支持一次拖多个。其它类型会提示一句，不会静默丢掉。`dragover` 里必须 `preventDefault()`，否则浏览器会把文件当页面导航，直接离开当前文档。

Chromium 还能在 drop 时取回真实句柄（`getAsFileSystemHandle()`），于是拖进来的文件直接绑定磁盘、改动写回原文件，和「本地文件夹」里的文件一样；**拖进来的是目录就直接当工作目录连上**。取不到句柄（Firefox / Safari）时退回拷贝进浏览器。

**文件夹工作空间**：文件菜单的「打开文件夹…」调起系统选目录对话框，最多向下四层查找 Markdown，跳过 `node_modules`、`.git`、`.obsidian` 之类的目录；带 `.obsidian/` 的文件夹会在扫描前被识别出来，改走库扫描（8 层、5000 个文件，见 [Obsidian 库](#obsidian-库)），不会被普通文件夹的上限悄悄截断。打开过的每个文件夹都记成工作空间，之后从「最近打开…」直接切回。文件绑定的是 `workspaceId + path`，所以两个根目录下的 `notes/index.md` 是两篇不同的文件，永远不会串写。

- 同一时刻只挂载一个工作空间。切换前会先把待写的改动落盘；写盘失败时由你选：重试、保留浏览器副本并继续切换、或取消切换。
- 最近工作空间与最近文件（跨工作空间、按 `workspaceId + path` 去重，最多 20 条）在同一个对话框里。从另一个工作空间的最近记录跳转时会先切根，再打开文件。
- 默认普通文件夹一次扫描最多收 2000 个文件、向下 4 层；Obsidian 库则是 5000 个文件、8 层，上限均可在设置中修改。无论哪种，触顶都会提示「只列出前 N 个」，不会假装列表是完整的。
- 目录句柄存在 IndexedDB 里，下次打开页面自动接回来；但写权限只在刷新时**查询**而不申请，过期时面板里出现「授权写入」按钮。只读根会明确显示只读状态，而不是悄悄写不进去。
- 改动按文档各自 600ms 防抖、串行写盘：同一篇文档不会有两个写操作交错。写盘失败（权限撤销、文件被删）会提示并保留浏览器里的改动，正文永远不丢。
- 覆盖前会先比对磁盘基准哈希。文件已被别的编辑器改过就进冲突对话框：采用磁盘版本，或把你的改动另存成 `-conflict` 副本。不会静默覆盖。
- 另存时同名文件已存在就自动让位成 `名称-2.md`，不覆盖别人的文件。
- 「断开工作空间」保留最近记录和你的文档；「从最近记录移除」只删掉句柄与元数据，绝不动磁盘上的文件。
- 只有 Chromium 内核（Chrome / Edge）支持这套 API。不支持的浏览器点「文件夹」会提示改用「导入」，不会静默失败。

**Obsidian 式实时编辑**是内置插件（`markpage.obsidian-live-editing`），**默认关闭**：在「设置 → 插件」里启用后，模式切换区会多出第四个模式。它是一条连续的 CodeMirror 6 视图，非活动行把标题、粗体、斜体、删除线、链接、列表和引用的标记藏起来直接呈现效果，光标所在行则原样显示 Markdown，可以就地改标记。Frontmatter、raw HTML、代码块和复杂公式刻意保留源码——不做有损序列化。Markdown 仍是唯一真相：每次输入都走和源码栏同一条 `commitEdit` 链路，修订、撤销栈、评论、工具栏格式和写盘行为完全一致。中文组字期间不提交、不改写，候选词落下后一次性提交；停用插件会安全回退到排版视图，正文一个字都不变。

## Obsidian 库

连上一个带 `.obsidian/` 的文件夹，MarkPage 就把它当库来读：Obsidian 的语法能渲染，链接在库内解析，改动写回 Obsidian 打开的那同一个文件。

只读 `.obsidian/app.json`（`attachmentFolderPath`、`useMarkdownLinks`、`newLinkFormat`），绝不写回 `.obsidian/` 下的任何文件，也不加载插件。

| 语法 | 行为 |
| :--- | :--- |
| `[[笔记]]`、`[[笔记\|别名]]` | 按 完整路径 → 相对路径 → 文件名（最短路径）→ 别名 解析后就地打开；解析不到的灰显，并列在链接面板里 |
| `[[笔记#标题]]`、`[[笔记#^块id]]`、`[[#本页标题]]` | 打开笔记并滚到该标题（按渲染出来的文字匹配，不依赖 slug）或该块。查找只在已排版出来的纸张里进行，分页用的离屏测量层永远不会抢走这次跳转 |
| `![[笔记]]`、`![[笔记#标题]]` | 内联渲染正文，**只读**：不输出源码偏移、不参与评论锚点，最多 3 层；循环或找不到目标时显示带来源标签的占位，右上角可跳过去 |
| `![[图片.png]]` | 走 blob URL 显示；查找顺序 绝对路径 → 相对本文目录 → `attachmentFolderPath` → 全库唯一文件名 |
| `[文字](笔记.md)` | 能解析到库里就当内链，否则仍是普通外链 |
| `> [!类型]`、`> [!类型]-`、`> [!类型]+` | callout，每种类型一套配色；`-` / `+` 折叠成 `<details>` |
| `#标签`、`#父/子` | 有标签样式且可点击 —— 点开预填该标签的快速切换 |
| `==高亮==` | `<mark>` |
| 块末尾的 `^块id` | 从正文里摘掉，记成 `data-block-id`，就是 `[[笔记#^块id]]` 的落点 |
| `%%注释%%` | 不显示 |
| frontmatter 的 `tags` / `aliases` | 参与索引、反向链接与快速切换 |

面板与对话框把这套东西串起来：

- **库目录树**（工作区面板）：文件夹可折叠、带 Obsidian 标记、显示附件数。
- **链接面板**：当前笔记的反向链接（带命中那一行做上下文），以及本文里所有还没解析的链接 —— 每条都能「新建笔记」，这是 MarkPage 唯一会**新建**文件的地方。索引中途停下时（文件数上限、64 MB 预算或某篇读不出来）面板会明说「索引不完整，部分链接可能无法解析」，不会把一份残缺的反链当成全貌。
- **快速切换**（`Mod+O`）：按标题 / 别名 / 路径模糊匹配，`↑` `↓` `Enter` `Esc`，输入 `#标签` 按标签过滤。
- **跟随双链**（`Mod+Enter`）打开光标所在的那个 `[[双链]]`；**新建笔记**（`Mod+Shift+N`）在当前笔记旁边建一篇未命名笔记（重名自动编号）并打开。
- **冲突对话框**：见下面的写回策略。

**写回**。Markdown 始终是唯一真相，MarkPage 从不整篇重写文件。页面设置只改它自己那几个键（`title` / `header` / `footer` / `paper` / `fontSize` / `lineHeight`），而且是逐行改写：键序、注释、引号风格、CRLF 换行全部原样保留；frontmatter 不是合法 YAML 时干脆不动，不会「顺手」重排成另一份。每次写盘前都比对文件的 mtime 与大小，发现别的程序改过就停下，弹出和别处同一份冲突对话框：*采用磁盘版本* 或 *保留我的改动、另存副本*。刻意不留「覆盖」这一项 —— 在选择之前自动写回一直是暂停的。写入走的是可写流，只有 `close()` 才真正替换文件，所以写到一半页面挂掉，原文件仍然完好，未落盘的改动留在浏览器副本里，下次打开自动重新排队。

库默认扫描到 8 层、5000 个文件，建索引时每篇最多读 512 KB、总量不超过 64 MB，结果按 mtime + size 缓存在 IndexedDB，所以重连大库很快。被预算挡下的笔记会按「不完整」缓存，而不是缓存成空文件 —— 否则重连一次，残缺的索引就会冒充完整索引，警告也跟着消失。建索引放在 Web Worker 里跑，环境不支持或中途出错就退回主线程。设置 → Obsidian 里可以开关语法增强与外部改动检测，也能一键重建索引。

明确不做：社区插件语法（Dataview、Templater、Excalidraw）、`.canvas`、图谱、发布 / 同步，以及在 MarkPage 里重命名或删除笔记 —— 重命名会打断所有指向它的链接，这件事该交给能更新链接的 Obsidian。

## 插件快捷键规范（API 1.2）

插件命令会出现在「设置 → 快捷键 → 插件」，插件菜单同时显示生效键位。API 1.2 新增可选的 `defaultBinding`、`allowWhileTyping`，现有 1.1 插件无需修改即可继续使用。

```ts
api.registerCommand({
  id: 'toggle-panel', // Globally unique; kebab-case, without a plugin: prefix.
  title: 'Toggle panel',
  defaultBinding: 'Mod+Shift+K',
  allowWhileTyping: false,
  run: () => togglePanel(),
})
```

键位统一写成 `Mod+Alt+Shift+Key`，`Mod` 在 macOS 为 Command，其他平台为 Ctrl；支持 Ctrl/Cmd/Meta、Alt/Option 别名。键名使用大写字母或 DOM 具名键（`Enter`、`ArrowLeft`、`F1`–`F12` 等）。裸字母和裸 Space 非法；必须带 Mod/Alt，或使用不会打断输入的具名键。浏览器保留的 `Mod+N`、`Mod+T`、`Mod+W`、`Mod+1`–`Mod+9` 不可使用，非法默认值会在设置中标明未绑定。

优先级为用户自定义、核心默认、按注册顺序的插件默认。插件默认冲突时保留先占用者，新命令未绑定；设置与每会话每插件一次的提示会说明占用者。默认值只在运行时合并，不写入用户设置。录制时统一检测核心与插件冲突，Backspace/Delete 清空、Escape 取消，单行恢复默认移除用户覆盖。主动清空的空串在刷新后保留；停用再启用恢复自定义。「全部恢复默认」也会清除孤儿插件的覆盖。同 id 命令只保留后注册的实现。录制期间及模态框打开时不派发插件命令；在输入框和实时编辑器中触发须声明 `allowWhileTyping: true`。插件无需自行监听键盘。

## 扫描预算与可选 Obsidian 桥接

「设置 → Obsidian → 扫描与索引上限（高级）」可以持久化修改六项上限。默认普通文件夹 4 层 / 2000，库 8 层 / 5000，索引单篇 512 KB / 总量 64 MB；深度范围 2–16，普通文件数 200–20000，库文件数 500–50000，单篇 64 KB–8 MB，总量 8–512 MB。非法设置回默认，有限数值限制在范围内。「标准」恢复全部默认，「大库」使用库 20000 文件、单篇 1 MB、总量 256 MB。修改后点击「重新扫描」生效。扫描只列目录，索引才读取内容，提高预算会增加首次索引耗时。截断提示使用实际生效的数字，不完整索引会保留提示。

可选的桌面伴生插件通过 Obsidian metadataCache 与 SSE 提供列表、索引、原文和附件，连接后不再走浏览器扫描 / 建索引。桥接只读；已有 FSA 绑定仍使用基准哈希与原有冲突处理。通过桥接打开的笔记先存为浏览器副本，显式另存才使用本地文件授权。请求或事件连接失败后恢复原挂载的 FSA 文件夹。[构建、手动安装、BRAT 发布资产与由你操作的验收步骤](obsidian-plugin/README.md)。构建不会自动发布版本。

## 修订模式

修订也写进 Markdown，源文件依旧是唯一真相：

| 语义 | 源码 | 正文显示 |
| :--- | :--- | :--- |
| 删除 | `~被删掉的字~` | 红色删除线 |
| 新增 | `<ins>新写的字</ins>` | 绿色下划线 |

单波浪号只用于修订，删除线仍然只认 GFM 的 `~~文字~~`（`remark-gfm` 的 `singleTilde` 已关掉）。

| 操作 | 结果 |
| :--- | :--- |
| 工具栏的修订开关 | 打开后正文里的修订标记可以点开「接受 / 拒绝」，状态栏出现 `N 处修订` |
| 源码里打字 | 新输入的内容自动套 `<ins>`，连续输入并入同一条；退格 / 删除选中内容则包成 `~…~`，相邻的删除标记自动合并 |
| 退格掉自己刚插入的字 | 直接消失，不会留下 `~…~` |
| 选中正文后点「标记删除」 | 选区包成 `~…~`，再点一次取消 |
| 选中正文后点「插入 / 替换」 | 弹窗输入新内容：原文留成 `~…~`，新内容写成 `<ins>…</ins>` |
| 点正文里的修订标记 | 浮层里单独「接受 / 拒绝」这一条 |
| 工具栏的「接受全部 / 拒绝全部」 | 整篇一次性处理 |

**公式与代码块不参与修订。** `$…$`、`$$…$$`、行内反引号、``` 围栏与 Frontmatter 都属于保护区：里面的编辑直接生效、不会被套标记，选中它们点「标记删除」会被拒绝并提示。带换行的粘贴、以及 `~ < >` 这类标记符号的手工输入也走直改，避免写出 `~~` 或把代码围栏塞进行内标签。输入法组字过程中不改写文本（会打断候选词），上屏后再一次性记为一条新增。

## 停靠侧边栏

左侧栏由若干**面板组**组成，每组 = 一条标签栏 + 一个内容区，默认「示例库 / 工作区 / 文档大纲」各成一组。

| 操作 | 结果 |
| :--- | :--- |
| 拖动面板标签到另一组的标签栏 | 两组合并，面板变成并排标签页（拖到标签左/右半边决定插入位置） |
| 拖动面板标签到底部虚线投放区 | 该面板拆成独立的新面板组 |
| 拖动标签栏右侧把手 | 调整面板组的上下顺序 |
| 标签上的 `×` / 右上角 `+` | 关闭面板 / 从列表里重新打开 |
| 拖动侧栏右边缘 | 调整宽度（双击复位 236px，范围 190–520；实际宽度再乘 `--ui-width`） |
| 面板组右上角按钮或工具栏图标 | 整栏隐藏 / 显示 |
| 标签聚焦后 `←` `→` / `Home` `End` / `Delete` | 切换标签 / 跳到首尾 / 关闭当前面板 |
| 侧栏右边缘聚焦后 `←` `→`（`Shift` 加大步长）/ `Home` | 键盘调宽 / 复位默认宽度 |
| `+` 菜单打开后 `↑` `↓` / `Esc` | 在面板列表里移动 / 关闭菜单 |

布局存在 `markpage.settings.v1` 的 `layout` 字段里，刷新、重开浏览器都保持原样；旧版本只有 `showOutline` 布尔值时会被自动迁移成默认布局。设置 → 通用 里可以一键恢复默认布局。窄于 1020px 时侧栏宽度固定为 200px 且隐藏拖拽把手，窄于 780px 时整栏收起、工具栏的显隐按钮也一并隐藏（否则会出现「按了没反应却改了状态」的假控件）。

## 多语言

`src/i18n/locales/` 下每个语言一份**扁平键值**词表：`zh-CN.ts` 是唯一真相源，`en-US.ts` 用 `Record<MessageKey, string>` 约束，漏翻一个键就编译不过。文案支持 `{name}` 占位符；**数字参数按当前语言格式化**（千分位），所以调用方要传原始数字而不是先 `toLocaleString()`。

复数走可选后缀：词表里写 `key.one` / `key.other`（也支持 `zero` / `two` / `few` / `many`），运行时按 `Intl.PluralRules` 选，没有对应变体就落回基础键。中文是单形态语言，只写基础键即可；英文给 `status.words`、`status.page` 这类带计数的文案补了 `.one`。

新增一门语言：

1. 复制 `src/i18n/locales/zh-CN.ts` 为 `xx-XX.ts`，翻译右侧的值（需要复数就补 `key.one` 等后缀键）；
2. 在 `src/i18n/index.ts` 的 `LOCALES` 数组里加一行 `{ id, label, short, htmlLang, messages }`（`label` 用该语言自称）；
3. 设置 → 语言 里自动出现这个选项，`<html lang>`、日期格式（`toLocaleDateString`）与数字格式一并跟着切换。

`npm test` 里的 `i18n/index.test.ts` 会守住三件事：每门语言覆盖全部键、同一文案的占位符集合与 zh-CN 一致、复数变体有兜底。

界面语言在首帧之前就从设置里读出来，不会先闪一下默认语言。翻译只作用于应用外壳：Markdown 正文、评论内容与 Frontmatter 永远原样保留。文档名留空即「未命名」，标签页、标题框与页面页眉统一按当前语言现算——翻译结果不会写进数据，所以切换语言时三处始终一致。

## 部署

`npm run build` 产出 `dist/` 纯静态文件，由 `.github/workflows/deploy.yml` 在推送到 `main` 时自动构建并发布到 GitHub Pages，无需提交构建产物。`vite.config.ts` 的 `base: './'` 使用相对路径，因此同一份构建产物也能直接放到 Vercel、Netlify 或任意子路径下托管。

同一次构建会并行发布到两个目标：GitHub Pages 与 Cloudflare Pages（`cloudflare` job 复用 `build` 的 `dist` 产物，凭证存于仓库 Secrets）。两份产物完全一致，互为镜像。
