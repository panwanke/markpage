# MarkPage 1.2.0：真实 Obsidian 测试清单

先按 README 生成并打开合成测试库。每项记录 PASS / FAIL / 未测试、实际
Obsidian 版本及现象。无需启动网页服务器。首轮不要用个人知识库。

## 1. 打开、模式和离线

- 启用 MarkPage，原生视图打开 `Start.md`，先切阅读模式。
- `Ctrl+P` 执行“MarkPage: 用 MarkPage 打开当前笔记”，出现独立窗格。
- 切换排版/双栏/源码。排版模式切分页/连续，公式、代码、callout 和本地图片可见。
- 断开网络，再次打开笔记；公式字体和本地图片仍正常。
- 检查普通原生窗格及其他插件的字体、颜色、快捷键没有改变。
- MarkPage 设置和底部显示 `1.2.0`、API 2、SHA；本地未提交构建带 `*`。

## 2. 编辑、标注和保存

- 双栏右侧源码把 `base-001` 改成 `markpage-002`，等待约一秒，状态变为“已保存”。
- 关闭 MarkPage，重新从原生视图读取文件，应能看到改动。
- 重新打开，分别测试选区加粗、高亮、文字颜色、右键菜单、评论/回复/解决。
- 分别在排版连续、排版分页、双栏预览中拖选普通正文：选区应可见，工具栏“添加评论”可用；提交评论后重新打开笔记，锚点和评论仍在。原生编辑器占用期间仍能选择并复制正文，但评论操作应禁用。
- 开启修订，输入与删除文字，分别测试接受/拒绝；撤销/重做恢复正确。
- 在“修订与映射”小节，保持修订模式关闭，直接点击“新增修订”或“删除修订”：应出现对应内容和“接受修订／拒绝修订”；关闭只收起操作区。分别验证接受新增保留文字、拒绝新增移除文字、接受删除移除文字、拒绝删除恢复文字，并测试撤销及重新打开后的保存结果。
- 只要文档含修订，紧凑工具栏也应显示“接受全部／拒绝全部”。拖选修订文字不应误打开处理面板。
- 拖选包含 `&amp;`、转义字符的整段映射测试文字后右键：应看到不可准确映射的解释，以及“复制文字／切到源码重新选择”；格式和评论应禁用。切到源码后重新选择可编辑内容再操作。普通正文选区仍应显示完整格式菜单。
- 在同段中只选“确映射的显示选区”等普通中文后右键：应出现完整格式菜单，可加粗或评论，前面的实体、转义、emoji 保持原样。分别检查浅色／深色主题：菜单按钮没有宿主默认的大块底色和阴影，文字清楚；受限菜单中的复制、切到源码可用，禁用项可辨认。
- 页面设置修改 header/footer，原 YAML 中 `tags`、`customProperty` 等仍保留。
- 用一份 CRLF 文件重复源码选区测试；变更应命中所选文字，未编辑行的换行不被统一重写。
- 在标题、评论或设置输入框中按撤销，不应撤销正文。中文输入法组字期间不应触发格式命令。

## 3. 链接、嵌入和多窗格

- 点击目标链接、第二节链接和块链接；应打开目标并定位，缺失目标仅提示，不创建新笔记。
- Ctrl/Cmd+点击 Markdown 目标，检查新窗格行为。
- 嵌入显示目标第二节，嵌入中的选区不能改写来源笔记。
- 打开链接面板，确认出链和反向链接；重命名目标后刷新并检查原生自动更新设置的实际影响。
- 为同一篇笔记打开两个 MarkPage 窗格。在一个源码框编辑，另一个立即反映；关闭一个后另一个仍能保存。

## 4. 原生编辑器占用

- 保留 MarkPage，在同文件的原生窗格切到 Source 或 Live Preview。
- MarkPage 应立即显示原生占用，源码框只读，格式操作不可用。
- 原生窗格输入 `native-003`，然后切阅读模式或关闭；MarkPage 应在落盘确认后显示新内容并恢复编辑。
- 原生纯阅读窗格不应一直阻止 MarkPage 写入。
- 若要验证“窗格关闭但尚未落盘”的间隙，可另按 `tools/obsidian-probe/README.md`
  执行诊断修订 2 的延迟写入用例；本次自动测试不能代替那份真实证据。

## 5. 外部修改和冲突

- 所有原生编辑窗格先关闭。在外部文本编辑器中打开测试库的 `Start.md`。
- MarkPage clean 时外部保存一行 `external-004`：MarkPage 自动更新，并开始新的撤销边界。
- 在 MarkPage 源码中持续输入，让 600ms 防抖尚未结束，同时在外部编辑器保存不同正文。
- 预期停止自动保存并显示冲突；磁盘保留外部版本，MarkPage 保留本地草稿。
- 选择“另存我的版本”，生成新的 `.markpage-copy-…md`，不覆盖原文件。
- 选择“载入外部版本”：先保留本地恢复副本，再显示磁盘版本；旧撤销不能覆盖它。

## 6. 删除、重命名和恢复

- 编辑测试笔记并在保存前删除原文件：应显示 missing，保留草稿，不自动重建。
- 重命名正在打开的笔记后继续编辑；应写入新路径，不写旧路径上后来新建的同名文件。
- 制造上一项冲突后禁用、重新启用插件，再打开原笔记，应提示恢复草稿。
- 选择恢复：若磁盘仍等于 base，可保存；若磁盘已变，应进入冲突比较。
- “恢复草稿”命令可查看未解决记录、另存或显式删除；不会自动过期丢弃草稿。
- 仅需测试强制终止时，用单独测试库进行；最后一次成功持久化之后的输入可能丢失。

## 7. 导出、更新和回退

- 直接导出与当前原始 Markdown 相同；纯净导出移除注释/高亮包装；自定义规则只影响副本。
- 先保存一条设置和一份未解决恢复记录，禁用插件，按 README 更新再回退。
- 检查 `data.json`、笔记及其他插件启用状态保留，重新启用仍能读取设置和恢复记录。
